# 常见问题

## 崩溃相关

### Q：打开就闪退怎么办？

先拿日志，比猜快一百倍：

```
/sdcard/Android/data/com.yg.aprs/files/crash.txt
```

这个文件由应用自带的 `CrashGuard` 写入，包含完整堆栈。没有这个文件（例如崩溃发生在
`CrashGuard.install` 之前）时用：

```bash
adb logcat -d -s AndroidRuntime:E
```

本项目历史上出现过三次启动闪退，根因都在 [CHANGELOG](../CHANGELOG.md) 里写明了：

| 版本 | 根因 |
|---|---|
| 1.1.0 之前 | `const/4 v5` 覆盖了仍当作字符串读取的 `v5` |
| 1.2.0 | 误用 `View.getChildAt`（应为 `ViewGroup`）→ 点图标闪退 |
| 1.3.0 | `.registers 3` + 2 个参数，`const-class v1` 覆盖了 `p0`(this) → 启动闪退 |

### Q：装上 1.3.0 一打开就闪退？

那是已知问题，升级到 **1.4.x** 即可。

### Q：点 APRS 图标闪退？

1.2.0 的问题（`getChildAt` 方法归属错误）。1.2.1 起图标行改为纯代码构建，1.4.x 正常。

## 状态显示相关

### Q：状态卡"网络"显示"未知"？

已修。原因：清单缺少 `ACCESS_NETWORK_STATE`，`ConnectivityManager.getActiveNetwork()`
抛 `SecurityException` 被兜底 catch 吞掉。1.2.2 起正常显示：

| 场景 | 显示 |
|---|---|
| 无网络 | 离线 |
| Wi-Fi | WiFi |
| 蜂窝 + 已给电话权限 | 中国移动 4G |
| 蜂窝 + 未给电话权限 | 中国移动 蜂窝 |

### Q：为什么蜂窝只显示"蜂窝"，不显示 4G/5G？

读网络制式需要 `READ_PHONE_STATE`（危险权限），本应用**没有**做运行时申请弹窗。
想要细分到 2G/3G/4G/5G：

```
系统设置 → 应用 → 极光信标 → 权限 → 电话 → 允许
```

不给也不影响上报，只是备注里的制式退化成"蜂窝"。

### Q：电量/电压、基站小区显示 `--`？

- 电量：部分 ROM 限制读取，或服务尚未取到第一帧状态
- 基站小区：需要定位权限 + 蜂窝网络；纯 Wi-Fi 环境读不到

### Q：定位源一直是"网络"不是"GPS"？

- 室内/车内 GPS 无信号时会退化到网络与基站定位（精度数百米）
- 检查系统定位是否开启、是否给了"精确位置"
- 首次冷启动可能需要 30–120 秒才拿到 GPS 定位

## 上报相关

### Q：App 显示在跑，aprs.fi 上却看不到我？

按顺序排查：

1. **密码对不对**：顶部胶囊是算出来的值，点一下复制。呼号写错一个字符密码就错
2. **服务器返回 `unverified`**：说明密码错。APRS-IS 会拒绝发送
3. **SSID**：aprs.fi 搜的是 `呼号-SSID`，比如 `BH6RGQ-15`，不是只搜 `BH6RGQ`
4. **间隔太长**：默认 60 秒，aprs.fi 也有索引延迟（通常 10–30 秒）
5. **位置非法**：见 [docs/APRS.md](APRS.md) 的"看不到我"一节
6. **aprs.fi 时间窗**：默认只显示最近 3 小时，用 `?timerange=` 调整

### Q：密码算出来是 `-1` / `0` / 数字很小？

- `-1` 表示当前没有连接 APRS-IS（只读观察用），不是密码
- 密码范围是 `0–32767`，出现很小的数字是正常的

### Q：aprs.fi 上「设备」显示 `Unknown: Unknown`？

aprs.fi 这个字段**只认报文的 TOCALL（目的地址）**，拿它去查软件登记表，查不到就是 Unknown。

- 1.4.2 起 TOCALL 由泛用的 `APRS` 改为专属的 **`APRGQ`**（报文里已经能看出是哪个软件）
- 要让它显示「极光信标」，需要把 `APRGQ` 登记进软件标识表：申请文本已写在
  [docs/APRS.md](APRS.md#8-设备名aprsfi-的设备字段)，发一封邮件即可
- 登记通过前显示 Unknown 不影响上报与轨迹显示，只是"设备"这一栏没人认识

### Q：怎么收发 APRS 消息？

1.5.0 起是「常驻连接」模式，收发都在一条连接上：

- **发**：填收件呼号 + 内容 → 点「发送」→ 消息进入队列，连接可用时立即发出，
  之后每 30 秒未收到 `ack` 会重发，最多 3 次
- **收**：服务器把 `::你的呼号 :正文{序号` 推下来，应用解析后存进收件箱，
  并自动回 `ack{序号`
- **看**：点「收件箱」按钮，下面会显示最近 12 条收到的消息 + 未确认的发件

### Q：怎么查看消息详情 / 快捷回复？

1.5.2 起：点「收件箱」→ 弹出消息列表（时间 + 来源 + 摘要）→ 点某一条 → 详情窗口：

- **快捷回复**：弹出输入框，发回给这条消息的来源呼号
- **复制正文**：复制到剪贴板
- 列表左上角还有**清空**

### Q：收件呼号怎么带后缀（如 BG6STN-9）？

1.5.2 起输入框允许 12 个字符，`-` 可以正常输入（中文输入法也行）。发送时会自动规范化：

| 你输入 | 实际发出的收件地址 |
|---|---|
| `bg6stn` | `BG6STN` |
| `BG6STN-9` | `BG6STN-9` |
| `bg6stn－15`（全角） | `BG6STN-15` |
| `BG6STN_9` | `BG6STN-9` |

顺带修了一个坑：主界面的「呼号」如果被填成 `BH6RGQ-15`，以前会拼成 `BH6RGQ-15-15` 导致
APRS-IS 拒收；现在启动和发消息前都会自动拆成 base + SSID 写回设置。

### Q：发了消息对方收不到？

- **对端必须在线**。APRS 消息没有服务器端排队，对端离线时消息直接丢失，
  本机的"重试"只是重连后补发，不能替代离线投递
- 收件呼号写全（`BG6STN` 或 `BG6STN-9`），不要带空格
- 看 `net.log` 里的 `msg out #03 -> BG6STN try=1`（已发出）与
  `msg ack #03 from BG6STN`（对方确认）两条记录即可判断卡在哪
- 一直 `未确认` 说明对端没回 ack（离线、或它的客户端不支持 ack）

### Q：为什么收到消息没有通知？

1.5.0 的收件箱只做"收藏"，不发通知——避免和前台服务通知抢注意力。
点「收件箱」即可查看；静默汇总通知在路线图里。

### Q：收件箱里的消息怎么没了？

收件箱/发件箱都保存在**内存**里。服务被系统回收、或手动停止上报后重启应用，内容会清空。
需要长期保存请等后续版本的本地存储（路线图）。

### Q：点「地图」后会打开什么？

按顺序尝试，能起来就用：

1. **百度地图 App**（`baidumap://map/marker`，带 `coord_type=wgs84`）
2. **高德地图 App**（`androidamap://viewMap`，坐标先做 WGS-84→GCJ-02 纠偏）
3. **系统地图选择器**（`geo:`，Google/华为地图等，按 WGS-84）
4. **高德网页版**（`uri.amap.com` 的免 key URI API，`coordinate=wgs84`）
5. **OpenStreetMap**（兜底）

如果提示"还没有定位数据"，说明本次运行还没成功上报过，先点「启动上报」等一轮。

### Q：内置地图是怎么实现的？要填 AK 吗？

1.6.0 的内置地图是 **WebView + 免 key 的网页地图**：

- 默认加载高德网页版 `uri.amap.com/marker?...&coordinate=wgs84`（官方免 key）
- 页内「百度页」用 `api.map.baidu.com/marker?coord_type=wgs84`（同样免 key）
- 页内「地图App」调用本机地图 App（百度 → 高德 → 系统 → OSM）

所以**不需要填 AK**。清单里预置的 `com.baidu.lbsapi.API_KEY` 是给"将来接真 SDK"留的，
现在不生效、也不影响任何功能。

### Q：地图上怎么看到别人的台站？

两种方式，都在地图页里：

1. **附近台站（列表）**：点「附近台站」，应用会向 APRS-IS 发 `filter r/纬度/经度/60`，
   订阅周边 60 公里的报文，读 8 秒后按距离列出（呼号 / 距离 / 方位 / 备注），点条目打开对方 aprs.fi 页。
   不需要 key，也不需要额外权限。
2. **aprs.fi（地图）**：点「aprs.fi」，直接加载以你为中心在线地图，能看到周边**所有**设备
   （包括不用本软件的电台、igate、中继）。

查不到台站的常见原因：周边 8 秒内确实没人发；或所用服务器过滤未生效（换 `rotate.aprs2.net` 再试）。

### Q：点「地图」闪退 / 百度地图进来就崩？

- **1.7.3 起主入口已回退为网页地图**，点「地图」不会再崩
- 想试百度原生的：网页地图页 →「百度SDK」。进入前会检查 ABI 与原生库，
  不满足会提示「当前设备不支持百度地图 SDK」并留在网页地图
- 如果「百度SDK」仍然闪退，那是**原生层崩溃**（不是 Java 异常，`crash.txt` 里没有），需要：

```bash
adb logcat -b crash -d > native.txt
```

  关键行：`Fatal signal 11 (SIGSEGV)` + `libBaiduMapSDK_*` / `libgnustl_shared.so` 的 backtrace。
  这份日志能直接判断是 GL 初始化、ABI 混用还是 SDK 自身问题。

### Q：地图页提示"百度地图初始化失败"怎么办？

1.7.2 之前的版本有个坑：百度 SDK **不给默认 marker 图标**，`MarkerOptions` 少了 `icon()`
就会抛 `BDMapSDKException: when you add marker, you must set the icon or icons`，
而旧代码把这条异常归到了"初始化失败"，于是自动降级到网页地图。1.7.2 已修（自己用 Canvas 画圆点当图标，
且 marker 失败不再影响地图本身）。

如果 1.7.2 之后仍看到这个提示，那就真是初始化问题了，页面上的错误文本能直接定位：

| 错误 | 含义 |
|---|---|
| `INVALID_USER_SCODE` / AK 相关 | AK 与「包名 + 签名 SHA1」不匹配（换过签名就会这样） |
| `UnsatisfiedLinkError: ... libBaiduMapSDK_*` | 设备 ABI 不支持（目前打包了 arm64-v8a 与 armeabi-v7a） |
| `privacy` 关键字 | 隐私合规未同意（应先 `setAgreePrivacy(true)` 再 `initialize`） |
| 网络类错误 | 设备连不上百度地图服务 |

### Q：怎么在地图上看到全国的其他 APRS 设备？

百度地图页点「**全国台站**」：向 APRS-IS 发 `filter b/17.5/73.0/54.5/135.5`
（中国范围外接矩形），读 12 秒，把收到的位置包去重后**批量打点**在地图上，
视野自动拉到全国；点任意标记可看呼号。

注意几点：

- 数据是"**此刻正在上报**"的台站，不是历史库 —— 某地没人开机就没有点
- 单次最多标 300 个（避免卡顿），想更全可以隔几分钟再点一次
- 每个点都做了 WGS-84 → GCJ-02 → BD-09，和百度底图对齐
- 想看更长时间窗的轨迹/历史，还是点「网页地图」或 aprs.fi 更合适（同源数据，它缓存更久）

### Q：为什么高德里的点比 aprs.fi 上偏了几百米？

坐标系不同：

- APRS / GPS 用 **WGS-84**
- 高德/腾讯用 **GCJ-02**（"火星坐标"，国内法规要求偏移）
- 百度用 **BD-09**

1.5.1 起对高德 App 做了 WGS→GCJ 纠偏、对百度传 `coord_type=wgs84`，误差应在几十米内（纠偏算法本身的精度）。
如果仍然偏，优先用第 3 步的系统地图或第 4 步的高德网页核对。

### Q：能不能接入高德 / 百度 / 腾讯地图 SDK（内置地图）？

能，但代价明确：

| 需要做的事 | 说明 |
|---|---|
| SDK 的 `.so` | 国产地图 SDK 都是原生渲染引擎，每个 ABI 十几 MB，APK 会从 4.9MB 涨到 20MB+ |
| API Key | 绑定 **包名 + 签名证书 SHA-1**，需要你在开发者控制台申请 |
| 隐私合规初始化 | 高德需先 `MapsInitializer.updatePrivacyShow/updatePrivacyAgree`，百度需同意隐私接口，否则地图空白 |
| 资源与清单合并 | aar 里的 res / manifest 要手工并进 `decoded/`，有冲突风险 |

本项目当前包名与签名指纹（申请 Key 时需要填）：

```
包名    com.yg.aprs
SHA-1   87:92:28:49:6A:FF:AE:E5:F6:53:AB:91:E5:58:E0:A1:06:78:6D:0A
```

真要做内置地图，需要先定：**哪个 SDK**、**你申请的 Key**，以及是否接受 APK 体积翻几倍。
没有真机反复试错的话，内嵌地图很容易出现"白屏/仅水印"。

## 后台与耗电

### Q：锁屏一会儿就停止上报了？

- 本应用使用前台服务 + WakeLock，理论上锁屏继续跑
- 但国产 ROM 会额外杀进程，需要手动设置：
  - MIUI：设置 → 应用 → 极光信标 → 省电策略 → **无限制**；允许自启动
  - EMUI/ColorOS/Flyme：允许后台活动 / 忽略电池优化
  - 通用：设置 → 电池 → 电池优化 → 找到本应用 → **不优化**
- Android 13+ 还需要允许通知，否则前台服务通知不显示（服务仍可运行）

### Q：切到后台就不上报了 / 一直显示上报失败？

1.4.3 起已修，原因有三个，都在连接层：

| 原因 | 现象 | 修法 |
|---|---|---|
| 复用长连接，后台网络切换后 socket 半死 | 界面显示"已上报"，aprs.fi 上没有点 | 每轮独立建连 + 失败重试 |
| 旧连接握手失败会整轮跳过 | 一个周期白等 | 轮询不再走旧连接分支 |
| 拿不到定位就整轮不发 | 状态停在「无定位」 | 补 10 分钟内的 lastKnownLocation |

如果升级后仍然中断，先看网络日志（1.4.3+ 才有）：

```
/sdcard/Android/data/com.yg.aprs/files/net.log
```

典型内容与含义：

```
11-22 22:31:05  connected asia.aprs2.net:14580 try=1 banner=# aprsc 2.1.15 logresp=# logresp BH6RGQ-15 verified, server T2ASIA
11-22 22:31:05  sent 52B: BH6RGQ-15>APRGQ,TCPIP*:!3050.78N/11419.05E>AURORA GPS 4G
11-22 22:32:08  attempt 1 failed: java.net.SocketTimeoutException: failed to connect to /xxx (port 14580) after 12000ms
```

- `logresp ... verified` = 密码正确；若是 `unverified`，说明呼号/密码不对
- `sent ...B` = 报文已写入 TCP；若连续出现 `failed`，多半是后台被限制联网，
  去系统设置里给应用「不受限制 / 允许后台联网」
- 日志为空说明服务没跑到发送阶段 → 检查是否被杀（见下面「锁屏一会儿就停止上报了」）

### Q：耗电吗？

间隔 60 秒 + GPS 常开时，约每小时 3–6% 电量（视机型）。想省电：

- 把间隔调到 300 秒以上
- 只在需要时启动，用完停止

## 其他

### Q：图标列表里图标和文字对不上？

图标按 ASCII 顺序与标签一一对应（`index = code - 0x21`）。若错位，说明
`arrays.xml` 的 `symbol_labels` 顺序被改动过——改顺序必须同时改 `symbol_icons` 与
`MainActivity.SYMBOL_CHARS`。

### Q：能做成标准 Gradle 工程吗？

技术上可以（把 smali 反编译回 Java 后重建），但工作量远大于收益，且容易破坏现有资源。
当前混合构建的好处是"改哪层都行"，见 [docs/BUILD.md](BUILD.md)。

### Q：支持 iOS / 鸿蒙 / 电脑吗？

只有 Android（8.0 / API 26 及以上）。鸿蒙可通过 Android 兼容层安装，未专门测试。

### Q：会收集我的数据吗？

不会。只与你设置的 APRS-IS 服务器通信，发送的就是 APRS 报文本身；设置仅存本机；
崩溃日志只写本地文件、不自动上传。详见 [SECURITY.md](../SECURITY.md)。
